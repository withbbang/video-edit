# 이미지 겹쳐 넣기 (로고·썸네일 오버레이) 설계

작성: 2026-10-29. 데스크톱 앱 결과 화면(스펙 `2026-10-22-desktop-app-design.md` 3.3)과 확대 타임라인
(`2026-10-28-filmstrip-timeline-design.md`)에 더한다.

## 1. 왜

사용자는 결과 영상 위에 **로고나 썸네일 같은 PNG 이미지**를 겹쳐 넣고 싶어 한다. 지금은 앱 밖의 편집기를 따로 써야 한다.
로고는 영상마다 거의 같은 자리에 넣으므로 한 번 맞춘 것을 **저장해 두고 다시 쓸 수 있어야** 한다.

## 2. 사용자가 정한 것

- 이미지는 PNG(로고·썸네일). **한 영상에 여러 장을 동시에** 띄울 수 있다.
- **위치·크기는 사용자가 정한다** — 영상 화면 위에서 끌어 옮기고, 모서리를 끌어 크기를 바꾼다.
- **나오는 시간 구간도 사용자가 정한다** — 시안 B: **확대 타임라인에 이미지마다 줄**이 하나씩 생기고,
  막대를 끌어 옮기고 양 끝을 끌어 구간을 정한다 (영상 편집 프로그램 방식). 시안 A(자막 탭 옆 목록에서 숫자로)는 고르지 않았다.
- **구간은 원본의 말에 붙는다.** 원본 1:20~1:35 에 붙인 썸네일은 나중에 그 안의 1:25~1:30 이 잘리면 결과에서 끊김 없이
  10초 동안 보이고, 잘린 곳이 되살아나면 다시 늘어난다. 결과 영상 시각에 고정하지 않는다.
- **로고 저장·재사용**: 이미지 + 위치·크기를 한 묶음으로 저장하고, 다른 영상에서 **직접 눌러서** 넣는다
  (자동으로 붙지 않는다). 넣으면 같은 자리·같은 크기로 처음부터 끝까지 붙는다.
- 아래 3장의 내 추측(새기기, 투명 배경, 실행 취소·저장, 프레임 격자, 이번에 뺄 것)에 사용자가 "맞다"고 했다.

## 3. 무엇을 만드나

### 3.1 화면

- **이미지 넣기**: 타임라인 쪽에 `이미지 넣기` 버튼 → 파일 고르기(PNG). 새 이미지는 지금 재생 위치부터 적당한 길이
  (빌더 판단, 예: 5초 또는 영상 끝까지 중 짧은 쪽), 화면 가운데 적당한 크기로 들어간다.
- **영상 위 편집**: 멈췄을 때(자막 줄 고치기처럼) 지금 시각에 떠 있는 이미지들이 영상 위에 보이고, 누르면 선택 테두리·
  모서리 손잡이가 생긴다. 끌어 옮기기, 모서리로 크기 바꾸기(가로세로 비율 유지 — 빌더 판단, Shift 로 풀기는 선택).
  재생 중에도 결과와 같게 겹쳐 보인다 (자막을 영상 위에 겹쳐 그리는 것과 같은 방식).
- **타임라인 줄**: 확대 타임라인의 화면 줄 위에 이미지마다 줄 하나 (이름 + 막대). 막대 끌기 = 구간 이동, 양 끝 끌기 = 시작·끝.
  잘린 곳은 다른 줄처럼 빗금으로 보인다. 줄에서 이미지를 고르면 영상 위에서도 선택된다. 삭제(Delete 키·버튼),
  겹침 순서(나중에 넣은 것이 위 — 순서 바꾸기는 빌더 판단, 없어도 됨).
- **저장해 둔 이미지**: 선택한 이미지에 `저장`(이름 붙이기) → 목록. 목록에서 누르면 그 영상에 처음부터 끝까지 같은 자리·크기로 들어간다.
  목록에서 지우기도 된다.

### 3.2 결과 파일

- 이미지는 **영상에 새긴다** (켜고 끄는 트랙은 없다). PNG 의 투명 배경은 그대로 살린다.
- 이미지가 하나라도 있으면 렌더 때 ffmpeg `overlay` 필터를 컷 뒤(결과 시간) 영상에 더한다. 자막 새기기(`--burn-subs`)와 함께 쓸 수 있고,
  이미지는 자막 **아래**에 깐다 (빌더 판단: 자막이 로고에 가리지 않게).
- 오디오만 있는 입력엔 이미지 기능을 숨기거나 막는다.
- **10비트/HDR 원본(아이폰 HLG 등)도 그대로 새긴다** (사용자 결정, 2026-10-29). PNG 를 HDR 색으로 바꾸지 않으므로
  로고 색이 조금 어긋나거나 밝게 보일 수 있는 것을 받아들인다. 막거나 경고하지 않는다. 자막 새기기도 지금 같은 처지다.

### 3.3 동작 규칙

- 위치·크기는 **영상 화면에 대한 비율**로 저장한다 (미리보기 영상은 긴 변 960 이하라 원본과 해상도가 다르고, 저장한 로고를
  해상도가 다른 영상에 넣을 수 있으므로). 저장한 로고를 가로세로 비율이 다른 영상에 넣을 때 이미지가 찌그러지지 않게
  이미지 자체 비율은 유지한다 (기준은 영상 너비 — 빌더 판단).
- 구간 시작·끝은 **원본 시간(초)**으로 저장하고 원본 프레임 격자(`get_result` 의 `fps`)에 맞춘다. 렌더 때 keeps 로 결과 시간
  구간들로 바꾼다 (원본 구간 ∩ 각 keep → 결과 시간, 이어지는 조각은 합침). 구간이 통째로 잘린 이미지는 결과에 안 나온다.
- 이미지 추가·이동·크기·구간·삭제는 `실행 취소`/`실행 재개` 대상 (`Api._snap` 에 포함). 옵션 변경은 지금처럼 제외.
- 영상별로 저장되어 앱을 다시 열어도 남는다: `out/<이름>.overlays.json` (자막 수정 `subs_edits.json` 과 같은 자리·같은 방식).
  전사가 바뀌어도 지우지 않는다 (원본 시간 기준이므로 전사와 무관).
- 이미지 파일은 사용자가 고른 경로를 그대로 믿지 않고 **작업 폴더로 복사**해 둔다 (원본을 옮기거나 지워도 렌더가 되게).
  저장한 로고는 사용자 데이터 폴더(`YTEDIT_DATA_DIR`, 맥 `~/Library/Application Support/youtube-edit`)의 하위 폴더에 이미지와 함께 둔다.

## 4. 이번에 하지 않는 것

- 서서히 나타나기/사라지기, 투명도 조절, 움직이는 이미지(GIF·영상), 회전.
- 새 영상에 저장한 로고를 자동으로 붙이기.
- PNG 외 형식 (JPEG 등은 빌더가 막지 않아도 되지만 요구 사항은 아님).
- CLI(`/youtube-clean` 스킬) 쪽 사용 흐름 — 파이프라인엔 앱이 부르는 숨은 옵션만 더한다.

## 5. 어떻게 (내 판단 — 빌더가 바꿔도 되지만 이유는 남긴다)

- **파이프라인**: 앱 전용 숨은 옵션 `--overlays <json>` 을 더한다 (기본 없음 = 기존 동작 그대로).
  json 은 `[{path, x, y, w, start, end}]` (x·y·w 는 영상 너비·높이 비율, start/end 는 원본 초). `render_video` 의 필터 스크립트에서
  `select…setpts` 뒤, 크롭 뒤에 `[n:v]scale=…[ovn]; [v][ovn]overlay=x:y:enable='between(t,a,b)+…'` 를 이어 붙이고 그 뒤에 `ass` 를 붙인다.
  enable 식이 길면 `sum_tree` 로 묶는다 (100항 제한). 이미지는 `-loop 1` 없이 정지 이미지 입력으로 충분한지 빌더가 확인.
- **앱**: `Job` 에 `overlays` 목록(id, 이미지 경로, x, y, w, start, end)을 더하고, `Api` 에 add/update/delete/save-preset/insert-preset
  호출을 더한다. `runner.render_command` 가 overlays.json 을 만들어 `--overlays` 로 넘긴다 (`save_subs_edits` 와 같은 모양).
- **순수 계산**(원본 구간 → 결과 구간, 비율 ↔ 화면 픽셀, 막대 끌기 스냅)은 `app/ui/timeline.js` 와 파이썬 쪽에 두고 테스트한다.
- 화면 문구는 데스크톱 앱 스펙 3장 문체를 따르고, 새 문구는 그 스펙 3장에 적어 둔다.
