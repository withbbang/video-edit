# 프레임 타임라인 (필름스트립 + 소리 파형) 설계

작성: 2026-10-28. 데스크톱 앱 결과 화면(스펙 `2026-10-22-desktop-app-design.md` 3.3)의 타임라인을 넓힌다.

## 1. 왜

결과 화면의 타임라인은 영상 전체를 높이 16px 막대 하나에 담는다. 10분 영상이면 1px 이 1초 가까이라
구간을 정확히 고를 수 없고, 막대에 그림이 없어 지금 고르는 곳이 어떤 장면·프레임인지 알 수 없다 (사용자 불편).
사용자가 원한 것은 다른 편집기처럼 **화면 아래에 프레임 썸네일이 이어 붙은 타임라인을 확대해서 그 위에서 구간을 고르는 것**이다.

사용자의 영상은 **1시간이 넘을 때도 있다** (30fps 기준 10만 프레임 이상).

## 2. 이미 된 것 (이 설계의 바탕, 커밋 전)

같은 날 먼저 만든 구간 다듬기 기능은 그대로 두고 새 타임라인에서도 똑같이 동작해야 한다 (스펙 3.3 에 반영됨):

- 구간 끝은 원본 프레임 격자 (`get_result` 의 `fps`, 모르면 30). `◀`·`▶`, ←/→ 1프레임, Shift+←/→ 10프레임.
  ←/→ 는 마지막으로 만진 끝(손잡이 강조)을 옮기고, 구간이 없으면 재생 위치를 옮긴다.
- `여기서 시작`(I)·`여기서 끝`(O), Shift+클릭 두 번(홀수 = 시작, 짝수 = 끝, 첫 점은 점선, Esc 취소). 그냥 클릭은 이동만.
- 코드: `app/ui/app.js` 의 `timeline()`·`pickEnd`·`shiftClick`·`stepEnd`·`makeRange`·`snapT`, `app/api.py` `get_result` 의 `fps`.

## 3. 무엇을 만드나 (사용자 결정: 시안 C)

재생기 바로 아래, 위에서부터:

1. **전체 막대** — 지금의 얇은 막대 그대로 (잘린 곳 빨강·되살린 곳 초록 점선·구간·재생 위치).
   여기에 **지금 아래 줄들이 보여 주는 범위를 노란 틀**로 겹친다. 막대를 누르면 지금처럼 그 위치로 이동하고,
   아래 줄들도 그 위치가 보이게 따라간다.
2. **화면 줄** — 프레임 썸네일을 시간 순서로 이어 붙인 줄. 잘린 곳은 빗금, 선택 구간은 파란 테두리·손잡이, 재생 위치는 세로선.
3. **소리 줄** — 소리 크기 파형. 화면 줄과 같은 시간 축. (말 영상에서 말 끝·숨소리·"어" 는 화면보다 파형에서 잘 보인다.)
4. **확대 조절** — `−`/`+` 와 슬라이더, ⌘(윈도우 Ctrl)+휠·트랙패드 벌리기로 확대·축소, 그냥 휠·가로 스크롤로 좌우 이동.
   가장 축소하면 영상 전체, 가장 확대하면 **썸네일 한 칸 = 1프레임**. 지금 몇 프레임/칸인지 짧게 보여 준다.

조작: 화면 줄·소리 줄 위에서 지금 타임라인과 같은 조작이 모두 된다 — 클릭 이동, 끌어서 구간 선택, 손잡이로 넓히고 좁히기,
Shift+클릭 두 번, ←/→·I/O. 재생 중 재생 위치가 보이는 범위를 벗어나면 줄이 넘어가 따라간다.
←/→ 로 구간 끝을 옮길 때도 그 끝이 보이게 따라간다.

## 4. 어떻게 (사용자가 정한 것)

- **썸네일은 비어 있다가 차차 채워져도 된다.** 분석 시간을 늘려서 결과를 열 때 다 준비해 둘 필요는 없다.
  그 사이엔 전체 막대·파형·재생기로 편집할 수 있어야 한다.

## 5. 어떻게 (내 판단 — 빌더가 바꿔도 되지만 이유는 남긴다)

- **썸네일 원본은 미리보기 영상** `jobs/<id>/preview/video.mp4` 를 쓴다. 긴 변 960 이하, **모든 프레임이 기준 프레임**(`-g 1`)이라
  아무 프레임이나 바로 디코딩된다. 원본(4K·HEVC·긴 GOP)을 다시 디코딩하지 않는다.
- **성긴 썸네일** (축소 화면용, 예: 1초에 1장 정도): 분석이 끝난 뒤 백그라운드에서 ffmpeg 로 미리보기 영상에서 뽑아
  타일 이미지(여러 장을 한 JPEG 에 격자로) + 색인으로 캐시한다. 처음부터 끝까지 조각 단위로 만들고, 조각 하나가 될 때마다
  화면이 받아서 채운다. 캐시는 미리보기 영상 서명으로 확인하고, 미리보기 영상이 바뀌면 다시 만든다.
  지금의 잘린 소리 미리보기(`app/preview.py` `CutAudio`)처럼 한 번에 하나씩, 앱 종료·영상 빼기 때 멈출 수 있게.
- **프레임 단위 썸네일** (성긴 간격보다 확대했을 때): 화면에서 숨은 `<video>` 로 미리보기 영상을 그 프레임에 맞춰 canvas 에 그린다
  (기준 프레임뿐이라 빠르다). 보이는 범위만, 메모리에 개수 제한을 두고 캐시한다. 서버 왕복·ffmpeg 를 부르지 않는다.
  성긴 썸네일이 아직 없는 구간을 확대하면 이 방식으로 바로 그린다.
- **파형**: 분석 때 이미 만든 분석용 오디오(`work/.../asr.wav`)의 에너지(`pipeline.load_rms`, 10ms 간격)를 dB 로 바꿔
  작게(예: 0~255 한 바이트씩) 한 번에 내려 준다. 1시간 ≈ 36만 값. 확대 수준에 맞게 화면에서 줄여 그린다.
  잘린 곳 판정에 쓰는 무음 기준선을 파형 위에 옅게 그려 주면 좋다 (빌더 판단).
- **언제·무엇을 만드나**: 결과 화면에서 **지금 열어 본 영상만** 만든다 (`get_result` 가 요청 — `CutAudio` 와 같은 자리).
  앱 시작 때 복원된 작업이나 업데이트 전에 분석한 작업도 열어 볼 때 만든다. 열지 않은 영상은 만들지 않는다.
  다른 영상을 열면 만들던 것은 멈추고(만든 조각은 캐시에 남김) 새 영상을 만든다. 영상을 목록에서 빼면 멈추고 캐시도 그 작업 폴더와 함께 지운다.
- **다른 실행과 함께**: 큐의 분석·저장과 **동시에 돌리되** 가볍게 — ffmpeg 스레드 수를 1~2 로 제한하고 낮은 우선순위로 돌린다.
  같은 영상의 파이프라인 실행(`run.lock`)과는 파일을 같이 쓰지 않는다 (미리보기 영상을 읽기만 하고 결과는 썸네일 폴더에만 쓴다).
  미리보기 영상이 다시 만들어지는 중이면(분석 중) 시작하지 않는다. `CutAudio` 와 일꾼은 따로 둔다 (잘린 소리가 썸네일 뒤에 밀리지 않게).
- **전체 막대의 조작은 지금 그대로 남긴다** — 클릭 이동, 끌어서 구간 선택, 손잡이, Shift+클릭 두 번 (2장 기능이 빠지지 않게).
  노란 틀은 표시만 하고 끌어서 옮기지 않는다. 범위 이동은 막대 클릭·아래 줄 스크롤·확대 조절로 한다.
- **옛 작업**(미리보기 폴더 없이 `preview_url` 만 있는 경우)·영상 없는 오디오 입력: 화면 줄은 비우거나 숨기고 파형만.
- 화면 문구는 스펙 3장에 추가한다 (CLAUDE.md 규칙).

## 6. 목표 · 하지 않을 것 · 실패로 보는 것

목표
- 1시간 넘는 영상에서도 확대해서 프레임 단위로 어느 장면인지 보며 구간을 고를 수 있다.
- 결과를 연 직후부터 파형·전체 막대로 바로 편집할 수 있고, 썸네일은 차차 채워진다.

하지 않을 것 (이번 범위 밖)
- 여러 트랙, 클립 옮기기·붙이기·리플 편집, 전환 효과. 자르기/되살리기 외의 편집 동작은 늘리지 않는다.
- 결과 영상(렌더)·SRT 에는 아무 영향 없음.
- 자막 줄을 타임라인 트랙으로 보여 주기 (나중 일).

실패로 보는 것 (동작은 해도 안 됨)
- 썸네일을 만드는 동안 재생이 끊기거나 화면이 굳는다 (스크롤·확대·끌기가 버벅임).
- 썸네일 때문에 분석·저장(렌더)이 눈에 띄게 느려지거나, 같은 영상을 다시 처리하는 실행과 부딪힌다.
- 캐시가 영상마다 수백 MB 씩 쌓인다 (1시간 영상 성긴 썸네일은 수십 MB 안쪽이 목표).
- 이미 된 구간 다듬기 조작(2장)이 새 타임라인에서 달라지거나 빠진다.
- 윈도우(WebView2)에서만 안 된다.

## 7. 제약

- 화면은 pywebview (맥 WKWebView, 윈도우 WebView2). 미리보기 파일은 `app/window.py` 의 로컬 HTTP 서버가 Range·CORS 로 내준다 —
  새 파일(썸네일 타일·색인)도 같은 길로 내준다 (`_PREVIEW_PATH` 허용 목록에 추가).
- ffmpeg 는 번들 바이너리 (`paths.ffmpeg_bin_dir`). 로컬 개발은 ffmpeg 9.x.
- 미리보기 영상의 프레임 속도와 원본 `fps` 는 다를 수 있다 (가변 프레임 원본 등). 구간 끝은 원본 프레임 격자(2장)를 따른다.
  화면 줄의 한 칸 = 1프레임 기준도 원본 `fps` 로 잡는다.
- 미리보기 재생기는 mse/fallback/legacy 세 방식이 있다 (`player.attach`). 숨은 `<video>` 는 재생기와 따로 둔다.
- 테스트: 파이썬은 pytest, JS 순수 함수는 `tests/test_player_js.py` 처럼 node 로. 파이프라인·앱을 고친 뒤 전체를 돌린다.

## 8. 빌더에게 맡기는 것

- 성긴 썸네일 간격(고정 1초인지, 영상 길이에 따라 바꿀지), 썸네일 크기, 타일 한 장에 몇 칸, JPEG 품질.
- 확대 단계·최대 축소 정의, 줄 높이.
- 파형 API 모양(새 Api 메서드 또는 파일로 내주기)과 크기 줄이는 방법.
- 썸네일 만들기를 파이프라인 옵션으로 둘지 앱 쪽 별도 실행으로 둘지 (단, 6장의 "부딪힘" 금지와 `run.lock` 규칙을 지킨다).
- `asr.wav` 가 없으면(옛 작업 등) 파형 줄을 숨긴다.
