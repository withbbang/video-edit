# youtube-edit 데스크톱 앱 설계

작성일: 2026-10-22
화면 시안: `.superpowers/brainstorm/7684-1792625391/content/` (`layout-v5.html`, `queue-v2.html`, `first-run-v3.html` 이 최종본)

이 문서에서 **(사용자 결정)** 은 사용자가 직접 고른 것, **(설계자 판단)** 은 대화 중 사용자가 맡긴 부분을
설계자가 정한 것이다. 설계자 판단은 더 나은 근거가 있으면 바꿔도 된다.

## 1. 왜 만드는가

지금은 `scripts/pipeline.py` 를 터미널에서 돌리거나 Claude Code 의 `/youtube-clean` 스킬로만 쓸 수 있다.
파이썬·터미널을 모르는 사람도 맥과 윈도우에서 **설치 파일을 더블클릭해 설치하고**, 영상을 끌어다 놓아
노이즈 제거 → 필러·말버릇·무음 컷 → SRT 자막까지 얻게 하는 것이 목표다.

핵심 경험: 결과를 본 뒤 옵션을 바꾸면 **몇 초 안에** 무엇이 더/덜 잘리는지 보이고, 그 자리를 원본/수정본으로
들어볼 수 있다. 마음에 들 때만 시간이 드는 최종 렌더("저장")를 한다.

## 2. 목표 / 비목표 / 실패 조건

**목표**
- macOS(.dmg) 와 Windows(설치 .exe) 설치 파일. 사용자 컴퓨터에 파이썬·ffmpeg 설치가 필요 없다.
- 드래그 앤 드롭과 파일 선택 둘 다로 영상을 넣는다. 여러 개를 한 번에 넣을 수 있다.
- 실행 전 옵션 선택, 진행 상황, 결과 요약, 결과 뒤 옵션 변경 시 차이 비교와 미리보기.
- 앱 업데이트 확인과 알림, 앱 버전에 묶인 모델 업데이트.

**비목표**
- 코드 서명·공증 (사용자 결정: 경고 넘기기 안내로 충분).
- 앱 스스로 바꿔 끼우는 자동 업데이트 (알림 + 설치 파일 내려받기까지만).
- 필러 사전(`fillers.json`)·감지 파라미터를 앱에서 편집하는 화면.
- 컷을 하나씩 손으로 켜고 끄는 편집기, 자막 편집기.
- 리눅스 배포.

**실패 조건 (동작해도 실패로 본다)**
- 기존 CLI(`pipeline.py`)와 `/youtube-clean` 스킬 동작이 바뀌거나 깨진다. 앱은 파이프라인 위에 얹는 것이지 대체가 아니다.
- 결과 뒤 옵션 변경에 수 분이 걸린다 (전사·오디오 정리를 다시 함).
- 앱 업데이트 때 2.8GB 모델을 다시 받는다.
- `input/` 원칙처럼 사용자가 넣은 원본 파일을 수정한다.

## 3. 사용자 화면 (사용자 결정)

### 3.1 기본 배치 — 한 화면 작업대 (시안 B)

창 하나. 왼쪽(좁게)은 위에 영상 목록, 그 아래 선택한 영상의 옵션. 오른쪽은 결과.

**왼쪽 옵션** (선택지 순서 그대로, 굵게가 기본값)

| 표시 이름 | 보조 설명 | 선택지 | 파이프라인 대응 |
|---|---|---|---|
| 망설임 | 아·어·음… | 유지 / **제거** | `--filler off/on` |
| 말버릇 | 그니까·약간·이제… | 유지 / **일부** / 모두 | `--habit off/on/aggressive` |
| 말 없는 구간 | | 유지 / **제거** | `--silence off/on` |
| 배경 잡음 | | 유지 / **제거** | `--denoise none/rnnoise` (3.5 참고) |
| ▸ 고급 (접힘) | | | |

**▸ 고급**

| 표시 이름 | 보조 설명 | 선택지 | 대응 |
|---|---|---|---|
| 음량 맞추기 | 유튜브 기준 크기(-14 LUFS)로 맞춤 | 유지 / **맞춤** | `--no-loudnorm` 반대 (3.5 참고) |
| 영상 안 자막 | mp4 안에 켜고 끄는 자막 트랙. SRT 파일은 항상 만듦 | 빼기 / **넣기** | `--embed-subs off/on` |
| 화질 | 자동: 1080p30 8Mbps · 4K30 약 32Mbps | 작게 / **자동** / 높게 | `--vbitrate` (작게·높게 배율은 설계자 판단: 0.6배 / 1.5배) |
| 저장 위치 | 현재 경로 표시 | [설정] 버튼 | `--out` 대신 최종 파일 위치 |

선택지는 세그먼트 버튼(가로로 붙은 버튼, 선택된 칸이 파랗게). 받아쓰기 모델 선택은 넣지 않는다 (사용자 결정).

**버튼**: 왼쪽 옵션 아래 하나, **오른쪽 정렬**. 실행 전 "시작", 결과가 나온 뒤 "저장".

### 3.2 영상 목록 (왼쪽 위)

- 각 영상은 박스 한 줄: 파일 이름 · 상태 · (진행 중이면 작은 진행 막대) · ✕.
- 맨 아래에 같은 박스 모양(점선 테두리)의 "＋ 끌어다 놓거나 파일 선택" 칸. 처음 영상이 없을 땐 오른쪽 전체가
  큰 끌어다 놓기 영역 + "파일 선택" 버튼.
- 창 어디에 떨어뜨려도 추가된다. 여러 파일을 한 번에 넣을 수 있고 파일 선택 창도 여러 개를 고를 수 있다.
- 처리 중에도 계속 넣을 수 있다. 영상은 **한 번에 하나씩 차례로** 처리한다.
- 목록에서 영상을 누르면 왼쪽 옵션과 오른쪽 결과가 그 영상 것으로 바뀐다. 새 영상은 기본 옵션으로 시작한다.
- 상태 문구: `대기` → `처리 중 62%` → `확인 대기` → `저장 중 40%` → `✓ 저장됨`. 실패는 `실패` + 이유 (설계자 판단).
- 처리 중 % 는 오디오 정리 + 받아쓰기 + 판정 전체 기준 (사용자에게 단계 구분을 보이지 않는다).
- "시작" 은 목록의 `대기` 영상 전부를 차례로 처리한다 (설계자 판단).
- ✕: 대기 중이면 목록에서 빼고, 처리·저장 중이면 확인 뒤 중단하고 뺀다 (설계자 판단).

### 3.3 결과 (오른쪽)

- 요약 한 줄: `12:41 → 10:58` · `214곳 잘림` · `−103초`.
- 미리보기 재생기: 잘린 곳을 뺀 결과를 이어 붙여 재생한다 (3.4).
- 그 아래 타임라인 막대: `■ 잘린 곳` 진한 빨강 `#d93036`, 되살린 곳은 초록 `#2a9d5c` 점선 테두리.
  설명 글자도 같은 색으로 칠한다. 막대를 누르면 그 위치로 이동 (설계자 판단).
- 타임라인을 끌거나, Shift+클릭 두 번(홀수 번째 = 시작, 짝수 번째 = 끝)으로 구간을 고른다
  (안내: `타임라인을 끌거나 Shift+클릭 두 번으로 구간을 선택하세요`, 시작만 찍었을 때
  `끝 위치를 Shift+클릭하거나 ‘여기서 끝’을 누르세요 (Esc 취소)`, 찍은 시작점은 점선). 그냥 클릭은 이동만 한다.
  `여기서 시작`(I)·`여기서 끝`(O) 은 지금 재생 위치로 정한다: 시작이 끝보다 뒤면 구간을 버리고 시작점만 찍고,
  시작 없이 끝만 정하면 영상 처음부터.
  시작·끝은 원본 프레임 단위(`fps`, 모르면 30)이고, `◀`·`▶`(1프레임)·←/→(1프레임, Shift 와 10프레임) 로 다듬거나
  시간 칸을 눌러 직접 입력한다 (`분:초.00`). ←/→ 는 마지막으로 만진 끝(강조 표시)을 옮기고, 구간이 없으면 재생 위치를 옮긴다.
  길이는 `(초 · 프레임)` 으로 보인다. `자르기`·`되살리기`·`취소`.
- `잘린 곳 N` · `자막 N` 탭과 목록은 재생기 오른쪽에 둔다. 오른쪽 화면은 통째로 스크롤하지 않고 목록만 스크롤한다.
- `잘린 곳` 목록은 `전체`·`말 없는 구간`·`망설임`·`말버릇`·`직접 자름`·`직접 되살림` 탭으로 나눈다.
  `전체` 에선 줄마다 종류 뱃지를 붙인다.
- 옵션을 바꿔 다시 판정해도 직전 결과와의 비교("달라진 곳")는 보여 주지 않는다 (사용자 결정).
- 타임라인 아래 범례(`■ 잘린 곳 · ▭ 되살린 곳`) 오른쪽 끝에 `↶ 실행 취소`·`↷ 다시 실행` (⌘Z·⇧⌘Z, 윈도우 Ctrl+Z·Ctrl+Y): 잘린 곳 되살리기·구간 작업·자막 고치기를
  한 단계씩 되돌린다. 옵션 변경은 넣지 않는다. 기록은 영상마다 100단계, 앱을 끄거나 받아쓰기가 바뀌면 사라진다.
- "저장" 을 눌러야 최종 파일을 만든다 (사용자 결정). 자동 저장하지 않는다.
- "저장" 은 목록에서 **선택한 영상 하나**에 적용 (설계자 판단). 저장 작업도 분석과 같은 한 줄 대기열로 돌리되,
  아직 시작 안 한 분석보다 앞에 끼운다 (사용자가 기다리는 작업 우선). 지금 돌고 있는 분석은 끊지 않는다.
- `✓ 저장됨` 영상에서 옵션을 바꾸면 다시 `확인 대기` 가 되고, 저장하면 같은 이름 파일을 덮어쓴다 (설계자 판단).

### 3.3.1 앱을 다시 켰을 때 (설계자 판단)

- 영상 목록, 영상별 옵션, 상태를 사용자 데이터 폴더에 저장해 다시 켜면 그대로 복원한다.
  분석 결과는 캐시에서 다시 읽으므로 받아쓰기를 반복하지 않는다.
- 처리·저장 도중 꺼졌던 영상은 `대기` 로 되돌린다 (받아쓰기는 중간 저장이 없어 처음부터).
- 원본이 옮겨지거나 지워진 영상은 `원본 없음` 으로 표시하고 ✕ 로만 뺄 수 있다.

### 3.4 미리보기와 들어보기 (렌더 없이)

- 다시 렌더하지 않는다. 미리보기는 남길 구간의 영상 조각과 완성본과 같은 방식으로 잘라 둔 소리를 이어 붙여(MediaSource)
  **결과 시간**으로 재생하므로 이음새에서 멈추지 않는다. 영상 아래 기본 컨트롤의 시간·길이·탐색 막대는 결과(완성 mp4) 기준이고,
  그 아래 타임라인·자막·`지금 위치로` 는 원본 기준이다. 멈춘 채 타임라인의 잘린 구간 안을 누르면 그 자리 화면을 보여 주고,
  재생하면 그 구간 끝부터 재생한다.
- 컷을 바꾸면 새 소리를 만드는 동안 지금 미리보기를 그대로 틀고 재생기 아래에 `미리보기 소리를 맞추는 중…` 을 보인다.
  준비되면 같은 원본 위치에서 이어 재생한다. 이어 붙이기를 못 쓰면(웹뷰가 지원하지 않거나 실패, 옛 미리보기) 예전처럼
  잘린 구간 시작에 닿으면 끝으로 건너뛰며 재생한다 (이음새에서 짧게 끊길 수 있음).
- `▶ 원본`: 그 컷 앞뒤 약 2초를 그대로 재생. `▶ 수정본`: 같은 구간을 컷을 건너뛰며 재생.
  (지금 화면엔 두 버튼이 없고 잘린 곳 줄을 누르면 `▶ 수정본` 처럼 원본 기준 그 컷 앞 2초부터 뒤 2초까지를 결과로 이어 재생한다.)
- 웹뷰가 원본 형식(mov, HEVC, 10비트, mkv 등)을 못 틀 수 있으므로, 처리 중에 **미리보기용 사본**을 만든다
  (긴 변 960 이하, 모든 프레임이 기준 프레임인 libx264 영상과 결과와 같은 소리의 AAC 를 따로 된 파일로.
  컷을 적용한 소리는 결과 화면에서 백그라운드로 따로 만든다).
  이 시간도 "처리 중 %" 에 포함한다.

### 3.5 결과 뒤 옵션 변경 — 빠른 것과 느린 것

- **빠름(몇 초)**: 망설임, 말버릇, 말 없는 구간. 캐시된 전사로 컷만 다시 판정한다 (`--review` 경로).
- **저장 때만 적용**: 배경 잡음, 음량 맞추기, 영상 안 자막, 화질, 저장 위치.
  지금 파이프라인은 배경 잡음·음량 설정이 분석용 오디오(`asr.wav`)와 전사 캐시 키에 들어가서, 바꾸면 전사를 다시 한다.
  앱에서는 이를 피하려고 **분석은 항상 기본 설정(rnnoise + loudnorm)으로 정리한 오디오로 하고**, 사용자가 고른
  배경 잡음·음량 설정은 최종 오디오에만 적용한다 (설계자 판단). 이를 위해 파이프라인에 "분석용 오디오 설정과
  출력용 오디오 설정을 따로 받는" 옵션을 추가한다. 기본값은 지금과 같게 둬서 CLI 동작은 그대로다.

### 3.6 처음 실행 — 모델 내려받기 (시안 A)

- 창 전체를 어두운 덮개로 가리고 가운데에 `모델 내려받는 중` / 진행 막대 / `1.1GB / 2.8GB · 약 4분 남음`. 다른 글자는 없다.
- 받는 동안 앱을 쓸 수 없다. 끊긴 곳부터 이어 받는다 (화면에 쓰지는 않음).
- 실패: `모델 내려받기 실패` / `인터넷 연결을 확인해 주시기 바랍니다` / [다시 시도].
- 앱 업데이트로 모델 목록이 바뀐 뒤 첫 실행에도 같은 화면 (3.8).

### 3.7 업데이트 알림

- 켤 때 한 번, 켜 둔 동안 24시간마다 GitHub 릴리스(`withbbang/video-edit`, 공개 저장소)의 최신 버전 확인.
- 새 버전이 있으면 창 위에 띠: `새 버전 1.2.0 · 바뀐 점 · 받기`. "바뀐 점" 은 릴리스 노트, "받기" 는 운영체제에 맞는
  설치 파일을 내려받아 연다. 설치는 기존 앱 위에 덮어쓴다 (맥: 응용 프로그램 폴더로 끌어 대치, 윈도우: 같은 위치 재설치).
- 띠 닫기(✕)는 그 버전에 대해 다시 띄우지 않는다 (설계자 판단). 네트워크 실패는 조용히 넘긴다.

### 3.8 모델과 앱 버전 묶기 (사용자 결정)

- 앱 안에 모델 목록(manifest)을 넣는다: Whisper(현재 large-v3-turbo 의 faster-whisper 변환본)와
  정렬 모델(`kresnik/wav2vec2-large-xlsr-korean`) 각각의 Hugging Face 저장소 이름 + 고정 리비전(커밋).
- 실행 시 사용자 데이터 폴더의 모델과 manifest 를 비교해, 다르면 3.6 화면으로 받고, 더는 안 쓰는 모델은 지운다.
- 모델은 설치 파일에 넣지 않는다 (2.8GB, GitHub 릴리스 파일당 2GB 제한). 모델만 따로 업데이트하는 경로는 없다.

## 4. 기술 선택 (설계자 판단, 사용자 승인: "웹 기술로 그린 창 하나짜리 데스크톱 앱, 파이썬 기반")

- **창/화면**: pywebview (맥 WKWebView, 윈도우 WebView2). 화면은 HTML/CSS/JS, 빌드 단계 없는 단순 구성 권장.
  드롭된 파일의 실제 경로는 pywebview 의 드롭 이벤트(전체 경로 제공)로 받는다. 파일 선택은 pywebview 의 네이티브 열기 창.
- **파이프라인 실행**: 앱이 영상마다 파이프라인을 **별도 프로세스**로 띄운다 (Windows ctranslate2 크래시 격리, 중단 가능).
  패키징된 앱 실행 파일이 숨은 인자로 파이프라인 모드로 동작하게 한다.
- **진행 상황**: 파이프라인에 기계가 읽는 진행 출력(예: `--progress-json`, 한 줄에 JSON 하나:
  단계, 0~1 비율, 메시지)을 추가한다. 받아쓰기 비율은 세그먼트 끝 시각 / 전체 길이, 렌더는 ffmpeg `-progress` 로.
  단계별 가중치는 빌더가 정한다.
- **패키징**: PyInstaller (또는 동급). 맥 Apple Silicon(arm64) .app → .dmg, 윈도우 x64 → Inno Setup 설치 .exe.
  ffmpeg/ffprobe 실행 파일을 함께 넣는다 (맥은 arnndn·VideoToolbox 포함 빌드, 윈도우는 arnndn 포함 정적 빌드).
- **인텔 맥은 지원하지 않는다** (설계자 판단). 릴리스 파일 이름과 README 에 "Apple Silicon(M1 이후) 전용" 을 적는다.
- **torch/transformers**: 필러 시간 보정(CTC)에 필요하므로 CPU 판으로 넣는다. 설치 파일이 수백 MB~1GB 대가 될 수 있다.
- **빌드/배포**: GitHub Actions 에서 `v*` 태그를 붙이면 맥·윈도우 설치 파일을 빌드해 GitHub 릴리스에 올린다.
- **윈도우 Whisper 장치 (사용자 결정: NVIDIA GPU 가 있으면 GPU, 없거나 실패하면 CPU)**:
  - CUDA 라이브러리(ctranslate2 가 요구하는 cuBLAS·cuDNN)는 설치 파일에 넣지 않는다. 첫 실행(또는 업데이트 뒤) 모델 받기 때
    NVIDIA GPU 가 감지된 PC 에서만 함께 내려받는다 (3.6 같은 화면, 용량만 늘어남). 버전은 3.8 manifest 에 같이 고정한다.
  - 받은 뒤 별도 프로세스로 GPU 로드 + 짧은 전사를 시험한다 (기존 `probe_whisper_windows` 방식). 실패하면 그 PC 는
    CPU 로 고정하고 기록해 다시 시험하지 않는다 (앱 업데이트로 manifest 가 바뀌면 다시 시험). 사용자에게 오류로 보이지 않는다.
  - GPU 가 없는 PC, 맥은 지금처럼. CPU 에선 받아쓰기가 영상 길이와 비슷하거나 더 걸릴 수 있음을 받아들인다 (사용자 결정).
  - 기존 `probe_whisper_windows` 의 CPU 실패 안내는 앱 화면의 `실패` 이유로 보여 준다.
- **라이선스 (사용자 결정)**: 앱과 저장소를 GPL 로 한다 (GPL ffmpeg 를 설치 파일에 넣기 때문). 저장소에 `LICENSE`(GPL-3.0)를 추가하고,
  설치 파일에 ffmpeg 라이선스 문구와 소스 위치를 함께 넣는다.

## 5. 파일 위치

- 앱 설치 폴더는 읽기 전용으로 본다 (맥 .app 안에 쓰지 않는다).
- 사용자 데이터 폴더: 맥 `~/Library/Application Support/youtube-edit/`, 윈도우 `%APPDATA%\youtube-edit\`.
  여기에 모델(HF 캐시), 영상별 작업 캐시(지금의 `work/<이름>/` 와 전사·컷 리스트), 앱 설정(옵션 기본값, 저장 위치,
  닫은 업데이트 버전), Windows probe 기록을 둔다.
- 파이프라인의 `ROOT` 기준 경로(`work/`, `models/sh.rnnn`, `fillers.json`, `.whisper_probe.json`)를 바꿀 수 있게 해야 한다.
  CLI 기본값은 지금과 같게 유지한다.
- 같은 이름의 다른 폴더 영상이 섞이지 않게 작업 캐시는 이름이 아닌 원본 경로 기준으로 구분한다 (설계자 판단).
- `fillers.json` 은 앱에 들어 있는 것을 쓴다. 사용자 데이터 폴더에 `fillers.json` 이 있으면 그것을 우선한다
  (편집 화면은 없음, 설계자 판단).
- **저장 결과**: 기본 저장 위치 `동영상/youtube-edit` (맥 `~/Movies/youtube-edit`, 윈도우 `%USERPROFILE%\Videos\youtube-edit`).
  `<이름>_clean.mp4`(오디오만인 원본은 `.m4a`)와 `<이름>_clean.srt` 만 둔다. 같은 이름이 있으면 덮어쓴다
  (CLI 와 같은 규칙). report/review/transcript 는 사용자 데이터 폴더에만 둔다 (설계자 판단).
- 원본 파일은 읽기만 한다.

## 6. 설치·첫 실행 안내 (README 와 릴리스 노트에 넣을 것)

- 맥: 처음 열 때 "확인되지 않은 개발자" 경고 → 시스템 설정 › 개인정보 보호 및 보안 › "그래도 열기".
  최신 macOS 에서는 우클릭 › 열기만으로는 안 되므로 이 경로를 그림과 함께 안내.
