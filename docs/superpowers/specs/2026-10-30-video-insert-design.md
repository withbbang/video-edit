# 영상 끼워 넣기 (다른 영상을 중간에 넣기) 설계

작성: 2026-10-30. 데스크톱 앱 결과 화면(스펙 `2026-10-22-desktop-app-design.md` 3.3), 확대 타임라인
(`2026-10-28-filmstrip-timeline-design.md`), 이미지 겹쳐 넣기(`2026-10-29-image-overlay-design.md`)에 더한다.

## 1. 왜

사용자는 영상 두 개 이상을 **하나의 결과 영상**으로 만들고 싶어 한다. 단순히 순서대로 잇는 게 아니라,
본 영상 A 의 **원하는 지점을 갈라 그 사이에 다른 영상 B 를 끼워 넣는** 방식이다. B 도 말하는 영상이라
A 와 똑같이 필러·무음 컷과 자막이 필요하다. 지금은 앱 밖 편집기로 미리 이어 붙인 뒤 앱에 넣어야 하고,
그러면 A 에서 해 둔 편집을 처음부터 다시 해야 한다.

자주 쓰는 **아주 짧은 영상**(인사말·구독 요청 등으로 짐작 — 사용자는 "자주 사용할 매우 짧은 영상"이라고만 함)은
이미지 보관함처럼 저장해 두고 다른 영상에 다시 넣고 싶어 한다.

## 2. 사용자가 정한 것

- 이어 붙이기는 **끝에 잇기가 아니라 끼워 넣기**: A 의 원하는 자리에서 갈라 B 를 넣는다.
- **B 도 A 와 똑같이 처리한다**: 필러·습관어·무음 컷, 자막. 결과는 지금처럼 영상 하나 + SRT 하나.
- **자주 쓰는 짧은 영상은 저장해 두고 다시 쓴다** (이미지 보관함과 같은 방식).
- **A 에서 이미 한 편집은 B 길이만큼 뒤로 밀려 그대로 살아남는다**: 직접 자르기·되살리기, 자막 수정(글자·줄 시간·꾸밈),
  이미지 위치·구간.
- **B 구간도 똑같이 편집된다**: 직접 자르기·되살리기, 자막 수정, 이미지 올리기. 앱 안에선 이어진 한 영상처럼 다룬다.
- 보관함 영상은 그 안의 편집(자막 수정·직접 자르기)도 같이 저장해 다음에 넣을 때 따라온다.
- 아래 3·4장의 내 판단(구간 빼기, 실행 취소, A 에 맞추기, 하지 않는 것)을 보여 줬고 사용자가 "진행해"라고 했다.

## 3. 무엇을 만드나

### 3.1 화면

- **영상 탭**: 오른쪽 목록의 `잘린 곳`·`자막`·`이미지` 옆에 `영상 N` 탭 (이미지 탭과 같은 모양 — 내 판단).
  윗줄 왼쪽 `사용 중 N`·`보관함 N`, 오른쪽 `불러오기`.
  - 사용 중: 이 작업에 끼워 넣은 영상 목록(작은 그림·이름·끼운 자리·길이). 누르면 고르고 그 자리로 이동.
    고른 줄에 `이름 변경`·`보관`(보관함에 저장)·`빼기`.
  - 보관함: 저장한 영상 목록 (`삽입`, ✕). 이름 두 번 누르기로 이름 바꾸기 (이미지 탭 규칙 그대로).
  - 소리만 있는 파일이면 탭을 숨긴다.
- **끼워 넣는 자리** = 지금 재생 위치 (원본 프레임 격자에 맞춤). `불러오기`(파일 고르기) 또는 보관함의 `삽입` 이 그 자리에 넣는다.
  재생 위치가 잘린 구간 안이면 어디로 붙일지는 빌더 판단(예: 그 잘린 구간의 시작으로 당김).
- **타임라인**: 확대 타임라인·막대에서 끼워 넣은 구간을 색 띠로 구분해 보인다. 띠를 누르면 영상 탭의 그 항목이 골라진다.
  그 밖의 편집(끌어 자르기, Shift+클릭, ←/→, 자막·이미지)은 이어진 한 영상 위에서 지금 그대로 동작한다.
- **처리 중 표시**: 넣은 영상을 전사·분석하는 동안 진행 표시를 보이고 그동안 편집은 막는다 (지금의 다시 판정과 같은 처지).
  A 는 다시 전사하지 않으므로 기다리는 시간은 B 길이에 비례한다.

### 3.2 동작 규칙

- **좌표계**: 앱의 모든 편집 시간(직접 자르기·되살리기·자막 줄 시간·이미지 구간)은 지금 "원본 초"로 저장된다.
  끼워 넣은 뒤엔 이 "원본"이 **이어 붙인 영상의 시간**이 된다. 즉 A 의 0~t, B 전체, A 의 t~끝 을 이은 시간.
- **넣을 때 밀기**: 자리 t 에 길이 d 인 B 를 넣으면 t 이후의 모든 편집 시간에 +d.
  - t 를 가로지르는 직접 자르기·남기기 구간은 t 앞뒤 두 조각으로 나눈다 (B 가 거기 휘말리지 않게 — 내 판단).
  - t 를 가로지르는 이미지 구간은 끝만 +d (이미지가 B 동안에도 이어서 보임 — 내 판단. 사용자가 막대로 고칠 수 있음).
  - 자막 줄은 조각 경계를 넘지 않는다. A 의 한 줄 가운데에 넣으면 그 줄은 두 줄로 나뉜다 (빌더가 자연스럽게).
  - 자막 수정은 지금 `"<seg id>:<어절 번호>"` 키와 전사 지문(`edits_sha1`)으로 저장된다. 이어 붙인 전사에선 세그먼트 번호와
    지문이 바뀌므로, **키를 새 전사 기준으로 옮겨** 수정이 지워지지 않게 해야 한다 (방법은 빌더 판단: 조각별 접두어 키 등).
- **빼기**: 끼워 넣은 구간을 빼면 넣기의 거꾸로 — B 구간 안의 편집(자르기·자막 수정·이미지)은 사라지고, 뒤쪽은 -d.
  B 구간에만 있던 이미지는 지운다. B 를 가로지르던 이미지는 B 만큼 줄인다.
- **넣기·빼기는 `실행 취소`/`실행 재개` 대상** (`Api._snap` 에 조각 목록도 포함). 실행 취소 때 미리보기·분석을
  다시 만들어야 하면 캐시를 써서 빨리 돌아오게 한다.
- **끼워 넣은 영상 안에 또 끼워 넣기**도 된다 (조각 목록이 평평한 순서이므로 B 를 갈라 C 를 넣는 것도 같은 규칙). 여러 개 가능.
  단위는 **넣은 영상(clip)** 이다 (내 판단): 같은 `clip_id` 의 조각들(B1·B2)이 한 묶음. 영상 탭엔 B 가 한 줄, 타임라인 띠는
  조각마다 그리되 같은 색·같은 항목. B 를 빼면 B1·B2 만 빠지고 그 안에 넣은 C 는 남는다. A 도 `clip_id` 하나(빼기 불가).
  `보관` 은 B 파일 전체를 저장한다.
- **자동 컷**: 이어 붙인 전체에서 지금 규칙 그대로 판정한다. 단 **조각 경계는 영상 맨 앞/뒤처럼** 다룬다 —
  B 의 앞뒤 무음은 전부 컷, 무음 잇기·자막 줄이 경계를 넘지 않음 (내 판단: 이음매에 빈 틈이 없게).
  필러 컷 경계 넓히기·CTC 보정도 경계를 넘어 다른 조각 소리를 건드리지 않는다.
- **A 에 맞추기**: 결과의 해상도·프레임 속도·회전·색(8비트 H.264 / 10비트 HEVC)·오디오 형식은 **A(맨 처음 영상)를 따른다**.
  B 의 화면 비율이 다르면 비율을 지켜 줄이고 남는 곳은 검은 여백. B 가 HDR 이고 A 가 SDR(또는 반대)이면 색 변환에서
  색이 조금 어긋나는 것을 받아들인다 (이미지 새기기와 같은 처지). B 에 소리가 없으면 그 길이만큼 무음.
- **소리 처리**: 노이즈 제거(`배경 잡음` 슬라이더)·음량 정규화는 모든 조각에 같은 설정으로 (내 판단).
  단 **추정하는 값은 파일마다 따로** 낸다 (내 판단): 자동 무음 기준(`silence_auto`)·말소리 중간값은 파일별로 계산해 그 파일의
  조각에만 쓰고, 음량 정규화도 파일마다 해서 파일 간 음량 차를 없앤다. 그래야 다른 방·마이크로 찍은 B 가 잘 잘리고,
  짧은 B 를 넣는다고 A 의 자동 컷이 바뀌지 않는다.
- **저장**: 조각 목록은 작업별로 저장되어 앱을 다시 열어도 남는다 (`Job` 에 저장, 이미지와 같은 방식).
  고른 영상 파일은 경로를 그대로 믿지 않고 **작업 폴더로 복사**한다 (원본을 옮기거나 지워도 렌더 되게 — 이미지와 같은 이유).
  A 원본(`input/` 또는 사용자가 고른 파일)은 건드리지 않는다.
- **보관함**: 사용자 데이터 폴더(`YTEDIT_DATA_DIR`)의 `clip_presets/` 에 영상 복사본 + 목록 json (이미지의 `overlay_presets/` 와 같은 모양).
  **보관할 때 그 영상 안의 편집도 같이 저장하고, 넣을 때 그대로 따라온다** (사용자 결정 2026-10-30):
  자막 수정(글자·줄 시간·꾸밈), 직접 자르기·되살리기. B 구간 안에만 있는 이미지도 같이 저장한다 (내 판단).
  편집 시간은 **B 파일 안의 초**로 저장한다 (B 가 C 때문에 B1·B2 로 갈려 있어도 같은 기준으로 뽑고 넣을 수 있게).
  B 를 가로지르는 이미지·구간은 B 안쪽 부분만 저장. 이미 보관한 영상을 다시 `보관`하면 같은 항목의 편집을 새것으로 바꾼다
  (덮어쓸지 새 항목으로 둘지 묻는 건 빌더 판단). 자막 수정 키는 B 단독 전사 기준으로 저장해 넣을 때 옮긴다.
  보관함 영상은 처음 한 번 전사·분석한 결과를 캐시해 두어 다음에 넣을 땐 거의 바로 들어가게 한다
  (캐시 키는 지금처럼 파일 지문 + 모델·prompt·노이즈 설정).

### 3.3 결과 파일

- 결과 이름·자리는 지금처럼 A 의 이름(`<A 이름>_clean.mp4`, `.srt`, …). cuts.json·review.md·report.md 도 이어 붙인 전체 기준.
  report.md 에 조각 목록(무엇을 어디에, 원래 길이)을 한 줄씩 적는다 (내 판단).
- 렌더는 **한 번만 인코딩**한다 (이어 붙인 중간 영상을 고화질로 미리 만들고 또 인코딩하는 이중 인코딩은 피한다 — 내 판단,
  4. 참고). 하드웨어 인코딩·실패 시 소프트웨어 재시도·자막 트랙·자막 새기기·이미지 겹치기는 지금 그대로 붙는다.

## 4. 이번에 하지 않는 것

- 장면 전환 효과(페이드·디졸브), 끼운 영상 자리 옮기기(빼고 다시 넣는다), A 자체를 잘라 순서 바꾸기.
- 끝에 이어 붙이기 전용 기능 (A 의 맨 끝을 재생 위치로 두고 넣으면 같은 결과).
- 소리만 있는 파일끼리 잇기, 소리 파일을 영상에 끼워 넣기.
- 조각마다 다른 노이즈·필러 설정.
- CLI(`/youtube-clean` 스킬) 사용 흐름 — 파이프라인엔 앱이 부르는 숨은 옵션만 더한다. CLI 기본 동작은 그대로.

## 5. 어떻게 (내 판단 — 빌더가 바꿔도 되지만 이유는 남긴다)

- **조각 목록**: `Job` 에 `pieces: [{id, src, name, in, out}]` (src 는 작업 폴더의 복사본 또는 A 원본, in/out 은 그 파일 안의 초).
  비어 있으면 A 하나 = 지금 동작. 넣기는 A 조각을 둘로 가르고 그 사이에 B 조각을 넣는 것.
- **파이프라인**: 숨은 옵션 `--sequence <json>` (조각 목록). 없으면 지금과 똑같다.
  - 분석 오디오(asr.wav)·정리 오디오·전사는 **파일마다** 만들어 캐시하고(지금의 캐시 규칙을 파일 단위로),
    조각의 in/out 으로 잘라 시간을 밀어 이어 붙인다. 그래서 B 를 넣어도 A 는 다시 전사하지 않는다.
  - 이어 붙인 전사의 지문(`transcript_sha1`)이 cuts.json·subs_edits 의 기준이 된다. `--apply-cuts` 는 지금처럼 지문이 다르면 멈춘다.
  - 렌더: 조각마다 입력을 열어 trim → A 에 맞게 scale/pad/fps/색 → concat 한 뒤 지금의 select·overlay·ass 로 넘긴다.
    소리는 이어 붙인 정리 오디오를 그대로 쓴다. 필터 식이 길어지면 `sum_tree`, ffmpeg 9 의 `-/filter_complex` 규칙 그대로.
  - 미리보기(preview video·audio_full·index)·썸네일·소리 줄도 이어 붙인 시간 기준으로 만든다. 미리보기 영상은 해상도가 낮아
    이어 붙여 다시 인코딩해도 싸다 (방법은 빌더 판단, 파일별 미리보기 캐시 재사용이면 더 좋다).
- **앱**: `Api` 에 `add_clip(job_id, at)` / `insert_clip_preset(job_id, pid, at)` / `remove_clip(job_id, piece_id)` /
  `rename_clip` / 보관함 `list/save/rename/delete_clip_preset` (이미지 쪽 함수 모양 그대로). 넣기·빼기는 편집 시간 밀기를
  한 곳(순수 함수, 테스트 쉽게)에서 하고, 그다음 다시 판정(rejudge) 흐름으로 B 만 전사·분석한다.
- **테스트**: 시간 밀기·가르기·빼기(직접 자르기, 되살리기, 줄 시간, 이미지, 자막 키 옮기기)는 단위 테스트.
  파이프라인은 합성 신호(`--denoise none`)로 짧은 A·B 를 만들어 이어 붙인 결과 길이·A/V 길이 차·자막 시간을 확인한다.
  해상도·fps 가 다른 B, 소리 없는 B 도 한 번씩.

## 6. 만들며 바뀐 판단 (2026-10-30)

- **넣는 자리**: 재생 위치를 결과 프레임 격자에 맞추고, 잘린 구간 안이면 그 구간 시작으로 당긴다. 넣은 영상 길이는 프레임 격자로 내린다.
- **자막 수정 키**: 넣기·빼기 동안 `"<clip>|<B 단독 seg id>|<어절>"` 키(`Job.stable_edits`)로 옮겼다가 다시 판정 뒤 새 전사 키로 푼다.
  파일 지문이 아니라 넣은 영상(clip) 기준이라 같은 파일을 두 번 넣어도 수정이 섞이지 않는다.
- **CTC 보정은 파일 단위**로 한다 (조각 단위가 아님). 옮기는 소리는 같은 파일 것이라 파일 캐시를 그대로 쓸 수 있고, A 를 가른
  자리 바로 옆 필러는 드물다 — 그 경우 필러 시간이 이웃 A 조각 쪽으로 갈 수 있다 (B 쪽 소리는 건드리지 않는다).
  컷 경계 다듬기는 조각마다 따로 하고 이음매에서 합치지 않는다.
- **실행 취소 캐시**: 조각이 없는 단독 실행도 `work/<이름>/files/<fkey>/` 의 파일별 캐시(분석 오디오·전사)를 키가 맞으면 쓴다 —
  넣기를 되돌려도 전사를 다시 하지 않는다.
- **실패 복구**: 넣은 뒤 다시 판정이 실패한(FAILED) 상태에서도 실행 취소·`빼기`가 된다 (늘 실패하는 B 에서 빠져나오게).
- **보관함 캐시**: 넣을 때 보관한 분석 캐시의 원본 서명을 작업 복사본 것으로 바꿔(`rebase_file_cache`) 옮긴다 — 캐시 키가 경로 기준이라
  그대로 복사하면 늘 빗나간다. 같은 영상을 다시 `보관`하면 묻지 않고 같은 항목의 편집을 새것으로 바꾼다.
- **자막 줄**: 조각 경계에서 멈춤이 없어도 줄을 나눈다 (실제 영상 확인에서 A 의 줄 가운데에 넣은 B 가 A 줄에 붙던 것을 고침).
