# 끼워 넣은 영상 옮기기 설계

작성: 2026-11-09. 영상 끼워 넣기(`2026-10-30-video-insert-design.md`)에 더한다. 그 설계 4장에서 "끼운 영상 자리 옮기기
(빼고 다시 넣는다)" 를 범위 밖으로 뒀던 것을 이번에 만든다.

## 1. 왜

지금은 끼운 영상 B 를 다른 자리로 보내려면 `빼기` → 재생 위치 옮기기 → 보관함에서 `삽입` 을 해야 한다.
번거롭고, 보관함에 넣어 두지 않았다면 B 안에서 한 편집(직접 자르기·되살리기, 자막 수정·꾸밈, B 위 이미지)이 빼는 순간 사라진다.
사용자는 끼운 영상을 **원하는 곳으로 바로 옮기고** 싶어 한다.

## 2. 사용자가 정한 것

- 옮기는 방법은 **두 가지 다**:
  1. **끌어다 놓기**: 타임라인의 끼운 영상 색 띠를 끌어서 원하는 곳에 놓는다.
  2. **버튼**: 타임라인 패널 머리 줄(`자르기`·`되살리기`·`취소` 가 있는 곳)에 다른 버튼처럼 **`옮기기`·`제거`** 버튼을 둔다.
     - **끼워 넣은 영상이 선택되었을 때만 활성화**, 선택되지 않았으면 비활성.
     - `옮기기` 는 고른 영상을 지금 재생 위치로 옮긴다.
     - 버튼에 마우스를 올리면 **설명 말풍선**이 뜬다.
- 버튼 문구는 **`옮기기`** (처음 제안한 "여기로 옮기기" 가 아님).
- B 안에 C 를 끼워 넣어 조각이 B1 · C · B2 로 갈라져 있을 때 B 를 옮기면 **가운데 C 까지 B 와 한 덩어리로** 옮겨진다.
- 영상 경계 근처의 잘린 구간에 놓으면 경계에 붙이는 자리 맞춤(3.2)을 **끼워 넣기에도 함께 적용**한다.

## 3. 무엇을 만드나

### 3.1 옮기는 단위 — 덩어리

- 영상 X 의 **덩어리** = 이어 붙인 시간에서 X 의 첫 조각 시작부터 마지막 조각 끝까지 (`_clip_views` 의 `start`~`end`).
  그 사이에 있는 조각(X 안에 끼운 C, C 안의 D …)이 모두 포함된다. X 에 끼워 넣은 것은 언제나 X 조각들 사이에 놓이므로
  덩어리 안에 A 나 관계없는 영상 조각이 끼지 않는다.
- 옮기기 = 덩어리를 통째로 떼어 새 자리에 다시 넣는 것. 조각 목록 순서만 바뀌고 **파일·조각 in/out 은 그대로**다.
- 덩어리 안의 편집은 같이 따라간다 (덩어리 안에 들어 있는 것 전부: X·C 의 직접 자르기·되살리기, 줄 시간, 자막 수정·꾸밈,
  덩어리 안에만 있는 이미지).
- **A("main")는 옮길 수 없다.** A 가 선택될 일은 없지만 API 도 막는다.
- C 처럼 다른 영상 안에 끼운 영상도 따로 옮길 수 있다. 그러면 C 덩어리만 빠지고, 빠진 자리에서 이어지게 된 B1·B2 는
  하나로 합친다 (`_merge_pieces`, 빼기와 같다).

### 3.2 놓는 자리

- 기준은 **옮기기 전 타임라인에서 사용자가 가리킨 시각 t** (끌어 놓은 곳, 또는 버튼일 때 재생 위치). 덩어리의 **시작**이 그 자리에 온다.
- t 는 원본 프레임 격자에 맞춘 뒤 (내 판단):
  - t 가 잘린 구간 안이고 **그 잘린 구간 안에 조각 경계가 있으면 t 에 가장 가까운 조각 경계로** 붙인다.
    조각 경계는 영상 맨 앞/뒤처럼 앞뒤 무음이 전부 잘리므로, 경계 근처에 놓으면 거의 늘 "앞 조각 꼬리 무음 + 뒤 조각 머리 무음" 이
    하나로 이어진 잘린 구간 안에 떨어진다. 구간 시작으로 당기면 앞 조각의 꼬리 무음 안으로 들어가 그 조각을 가르게 된다
    (예: A1·B·C·A2 에서 B 를 C 끝에 놓았는데 C 안에 끼워져 C1·B·C2 가 되고, 그 뒤 C 를 옮기면 B 가 끌려감).
    사용자는 화면에서 "영상 사이"에 놓은 것이므로 경계에 붙이는 것이 뜻에 맞다.
  - 그 밖에 잘린 구간 안이면 넣기처럼 그 구간 시작으로 당긴다.
- "덩어리 안" 판정은 **맞춘 뒤의 t** 로 한다. t 가 덩어리 **안**(시작 < t < 끝)이면 옮기지 않는다.
  덩어리 시작·끝과 같으면 제자리이므로 아무 일도 하지 않는다(실행 취소에도 안 쌓임). 덩어리 바로 뒤 경계에 놓는 것은 경계 규칙 덕에
  "끝과 같음"(제자리)이 되고, 덩어리 꼬리 무음 안으로 당겨져 막히는 일은 없다.
- 화면(끄는 동안 세로선)과 API 가 같은 규칙을 쓴다. 화면 쪽은 미리보기이고 최종 맞춤은 API 가 한다.
- **끼워 넣기에도 같은 규칙을 쓴다 (사용자 결정).** 지금 `불러오기`·보관함 `삽입`(`_insert_file`)은 잘린 구간 시작으로만 당겨
  같은 문제가 있다. 자리 맞춤을 한 함수로 묶어 넣기·옮기기가 함께 쓴다 (예: `sequence.snap_at(pieces, cuts, t, fps)`).
- t 가 다른 끼운 영상 안이면 그 영상을 가르고 들어간다 (넣기와 같은 규칙 — 내 판단).
- 계산: 덩어리 [s, e] (길이 d) 를 빼고(`shift_for_remove` 처럼 뒤쪽 −d), t 가 e 뒤였으면 t − d 자리에 넣는다(`shift_for_insert` 처럼 +d).
  덩어리 안의 편집은 빼기에서 지우지 말고 따로 떼어 두었다가, 새 자리 기준으로 시간만 옮겨 다시 붙인다.

### 3.3 덩어리 경계에 걸친 편집 (내 판단)

- **이미지**: 덩어리 밖에서 시작하거나 밖에서 끝나는 이미지는 제자리에 남고, 빼기 규칙대로 덩어리 길이만큼 줄었다가
  새 자리가 그 이미지 구간 안이면 넣기 규칙대로 다시 늘어난다. 덩어리 안에만 있는 이미지는 덩어리와 같이 간다.
- **직접 자르기·되살리기 구간**: 덩어리 경계를 넘는 구간은 경계에서 둘로 나눠, 안쪽은 따라가고 바깥쪽은 남는다.
- **자막**: 수정·꾸밈은 `clip|sid|w` stable 키(파일별 전사 기준)라 덩어리를 옮겨도 키가 바뀌지 않는다. 넣기·빼기처럼
  `stable_edits` 로 옮겼다가 다시 판정 뒤 새 전사 키로 푼다. 줄 시간(`line_times`)은 시간이 바뀌므로 위 규칙으로 옮긴다.

### 3.4 옮긴 뒤

- 조각 순서가 바뀌면 이어 붙인 전사·조각 경계가 바뀌므로 **다시 판정**한다 (넣기·빼기와 같은 흐름 `_restructure` → `rejudge`).
  파일별 캐시가 있어 **전사는 다시 하지 않는다**. 그동안 진행 표시·편집 잠금은 지금 넣기와 같다.
- 옮기기는 **`실행 취소`/`실행 재개` 대상** (`_snap` 에 조각 목록이 이미 들어 있음).
- 다시 판정이 실패한(FAILED) 상태에선 옮기기를 막는다 (빼기만 허용하는 지금 규칙 유지 — 내 판단).
- 옮긴 뒤에도 그 영상은 계속 선택돼 있고, 재생 위치는 옮겨 간 덩어리 시작으로 간다 (내 판단).

### 3.5 화면

**타임라인 머리 줄 버튼**
- `자르기`·`되살리기`·`취소` 묶음 옆에 `옮기기`·`제거` 를 둔다 (같은 `btn` 모양).
- 끼워 넣은 영상이 선택돼 있고(`S.clipSel`, A 아님) 편집할 수 있는 상태일 때만 활성화. 처리 중(다시 판정 중)이면 비활성.
- `옮기기`: 고른 영상을 지금 재생 위치로 옮긴다. 재생 위치가 그 덩어리 안이면 비활성.
- `제거`: 지금 영상 탭의 `빼기` 와 같은 동작 (`Api.remove_clip`).
- 말풍선 문구 (내 판단, 사용자 확인 전):
  - `옮기기`: "고른 영상을 지금 재생 위치로 옮깁니다" / 재생 위치가 그 영상 안일 때: "재생 위치를 고른 영상 밖으로 옮기세요"
  - `제거`: "고른 영상을 결과에서 뺍니다 (실행 취소로 되돌릴 수 있음)"
  - 선택된 영상이 없을 때 (두 버튼): "타임라인 띠나 영상 탭에서 끼워 넣은 영상을 고르세요"
- 말풍선은 앱의 다른 버튼처럼 `title` 로 단다. 맥(WKWebView)·윈도우(WebView2)에서 비활성 버튼의 `title` 이 안 뜨면
  버튼을 감싼 요소에 달거나 작은 CSS 말풍선으로 바꾼다 (빌더 판단 — 비활성일 때도 이유가 보여야 한다).

**영상 탭**
- 고른 줄의 `빼기` 를 **`제거`** 로 이름을 바꾼다 (내 판단: 같은 동작에 이름이 둘이 되지 않게). 영상 탭엔 `옮기기` 를 두지 않는다.
- 데스크톱 앱 스펙(`2026-10-22-desktop-app-design.md`)·영상 끼워 넣기 스펙의 해당 문구도 함께 고친다 (CLAUDE.md: 화면 문구는 스펙 그대로).

**끌어다 놓기**
- 대상: 확대 타임라인의 영상 줄 띠(`cl-band`)와 전체 막대 아래 얇은 띠(`cl-strip`) 둘 다.
- 띠를 눌렀다가 거의 움직이지 않고 떼면 지금처럼 그 영상을 고르고 그 자리로 이동한다. 몇 px(빌더 판단, 4px 안팎) 넘게 움직이면 끌기로 본다.
- 끄는 동안: 덩어리 전체 띠(조각이 여러 개면 모두)가 흐리게 표시되고, 놓일 자리(3.2 규칙으로 맞춘 t)에 세로선을 그린다.
  놓을 수 없는 자리(덩어리 안)면 세로선을 그리지 않는다. 띠 모양을 마우스 따라 같이 움직일지는 빌더 판단.
- 확대 타임라인에서 끌다가 보기 범위 끝에 닿으면 자동으로 스크롤할지: 빌더 판단 (없어도 됨 — 전체 막대로 멀리 옮길 수 있다).
- `Esc` 로 끌기를 취소한다. 놓으면 3.2·3.4 대로 옮긴다.

## 4. 이번에 하지 않는 것

- A 자체를 잘라 순서 바꾸기, 여러 영상 한꺼번에 고르기·옮기기.
- 덩어리 일부만 옮기기 (B 를 옮기면서 C 는 남기기).
- 끄는 동안 실시간 미리보기 (영상·소리를 옮겨진 순서로 바로 들려주기).
- 장면 전환 효과, 끝에 이어 붙이기 전용 기능.
- CLI 쪽 변화 없음 — 파이프라인은 조각 목록(`--sequence`)만 받으므로 손댈 일이 없어야 한다.

## 5. 실패로 보는 것

- 옮긴 뒤 덩어리 안 편집(자르기·되살리기·자막 수정·꾸밈·이미지)이 하나라도 사라지거나 엉뚱한 자리로 간다.
- 덩어리 밖 편집이 덩어리 길이만큼 정확히 밀리거나 당겨지지 않는다.
- 옮기기 때문에 전사를 다시 한다.
- 실행 취소 한 번으로 옮기기 전과 똑같이 돌아오지 않는다.
- 띠를 짧게 눌러 고르던 동작이 끌기로 잘못 잡혀 영상이 옮겨진다.
- 두 영상 사이에 놓았는데(또는 끼워 넣었는데) 이웃 영상이 갈라져 그 안에 들어가거나, 보이지 않는 짧은 조각이 남는다.

## 6. 어떻게 (내 판단 — 빌더가 바꿔도 되지만 이유는 남긴다)

- **순수 함수** (`app/sequence.py`): `move_block(pieces, clip, t)` → 새 조각 목록과 덩어리 (s, e, 새 시작),
  `shift_for_move(e, s, e_, t)` → 덩어리 안 편집은 새 자리로, 밖은 −d/+d. 기존 `_rm_span`·`_ins_span`·`_convert` 를 재사용.
  테스트는 `tests/` 에 넣기·빼기 테스트처럼.
- **API** (`app/api.py`): `move_clip(job_id, clip, at)` — `remove_clip`·`_insert_file` 과 같은 잠금·확인(`_can_restructure`),
  `_snap` → 계산 → `_restructure` → `rejudge`. 조각 경계를 맞춘 뒤 `_merge_pieces`. 반환은 넣기와 같은 `{"clips", "history"}`.
- **화면** (`app/ui/app.js`, 계산은 `app/ui/timeline.js`): 버튼은 `rangeBar.acts` 옆이나 같은 머리 줄에, 끌기는 `band()` 의
  pointerdown 을 끌기 판정으로 바꾼다. 놓을 자리 계산(덩어리 안인지, 격자·잘린 구간 맞춤의 화면 쪽 미리보기)은 `TL` 에 두고
  `tests/test_timeline_js.py` 에서 node 로 테스트. 최종 자리 맞춤은 API 가 다시 한다.
- CLAUDE.md 의 데스크톱 앱 절 "영상 끼워 넣기" 에 옮기기(`Api.move_clip`, 머리 줄 `옮기기`·`제거`, 띠 끌기)를 한 줄 더한다.
