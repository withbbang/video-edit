# 음원(BGM) 넣기 — 설계

2026-11-10

## 1. 왜

유튜브 영상의 인트로·엔딩, 그리고 그 밖에 원하는 곳에 BGM 을 깔고 싶다. 그 구간엔 말소리와 BGM 이 같이 나온다.
그래서 BGM 하나 안에서도 음량이 그림처럼 이어지며 바뀌어야 한다 — 말할 땐 낮아지고, 말이 끝나면 다시 올라온다.
지금 앱은 컷·자막·이미지·영상 끼워 넣기까지 되지만 소리를 더하는 방법이 없어, 다른 편집 프로그램으로 한 번 더 가야 한다.

성공: 앱 안에서 BGM 을 넣고, 말소리 구간이 자동으로 낮아진 음량 선을 받고, 점을 끌어 다듬고, 미리보기로 바로 들어 본 뒤
그대로 저장하면 결과 mp4 에 섞여 나온다.

## 2. 목표 / 하지 않을 것 / 실패로 보는 것

**목표**
- 결과 영상의 원하는 시점에 BGM 을 여러 개 넣는다. 겹치면 섞여 들린다.
- BGM 마다 점과 직선으로 된 음량 곡선. 넣을 때 말소리 구간을 낮춘 곡선이 자동으로 깔린다.
- 옮기기(끌기)·양끝 잘라 짧게 쓰기·고르기(active/inactive)·보관함.
- 미리보기에서 바로 들리고, 결과 mp4/m4a 에 섞인다. 실행 취소 대상.

**하지 않을 것**
- 곡보다 길게 늘리기, 반복(루프) 재생.
- 원본 위치(말)에 붙여 같이 움직이는 고정 방식 — 나중에 필요하면 추가.
- 영상 파일에서 소리만 꺼내 BGM 으로 쓰기.
- 곡선을 붓으로 자유롭게 그리기, 박자 맞춤, 곡 속도·음높이 바꾸기.

**실패로 보는 것 (기술적으로 돌아가도)**
- BGM 이 필러·무음 컷을 따라 툭툭 끊긴다. → BGM 은 결과 시간 위에서 끊김 없이 흐른다.
- 사용자가 손댄 곡선이 컷이 바뀌었다고 버튼 없이 덮어써진다.
- BGM 이 전사·컷 판정·자막에 영향을 준다, 또는 배경 잡음 제거에 BGM 이 같이 지워진다.
- 미리보기 소리와 결과 파일 소리가 다르다 (곡선·위치·음량).

## 3. 사용자가 정한 것

- **시간 기준: 결과 영상 시간.** 넣으면 지금 재생 위치에서 시작한다. 앞쪽 편집(컷·영상 끼워 넣기)이 바뀌어도
  BGM 은 그 결과 시간에 그대로 있다 (프리미어·캡컷과 같은 일반적인 방식). 장면과 어긋나면 사용자가 끌어 옮긴다.
- **음량 곡선 = C안.** 점과 직선. 선을 누르면 점이 생기고, 점을 위아래로 끌면 음량, 좌우로 끌면 시점.
  처음 넣을 때 말소리 구간을 낮춘 곡선을 자동으로 깐다.
- **자동 곡선 다시 깔기:** 점을 하나라도 손댄 BGM 은 컷이 바뀌어도 곡선을 그대로 둔다.
  막대의 **`음원 자동 조절`** 버튼을 눌렀을 때만 새로 깐다 (손댄 점은 지워짐). 버튼에 마우스를 올리면 말풍선:
  > 말소리가 나오는 구간은 BGM을 낮추고, 말이 없는 구간은 다시 올리는 음량 선을 새로 깔아요. 손으로 고친 점은 지워져요.
- **길이:** 곡 길이보다 길게 늘릴 수 없다 (반복 없음). 양끝을 안쪽으로 끌어 곡 앞뒤를 잘라 짧게 쓰는 건 된다.
- **고르기:** 끼워 넣은 영상처럼 누르면 active, 나머지는 inactive(흐리게).
- **끌어 옮기기 자리 맞춤**
  - 결과 영상 맨 앞에 닿으면 BGM 시작 = 영상 시작(0초), 맨 끝에 닿으면 BGM 끝 = 영상 끝.
  - 끼워 넣은 영상이나 다른 BGM 의 경계를 지나면 그 경계에 맞춘다 (영상 끼워 넣기의 자리 맞춤처럼).
- **겹침:** 두 BGM 이 겹치면 둘 다 섞여 들린다. 새 BGM 을 기존 BGM 사이에 넣을 수 있다 (밀거나 막지 않음).
- **관리:** 오른쪽 목록에 `음원` 탭 — `사용 중`·`보관함`, `불러오기`, 고른 음원 `이름 변경`·`보관`·`제거`, 보관함 `삽입`.
  이미지·영상 탭과 같은 구성.
- 미리보기에서 바로 섞여 들리고 점을 끌면 바로 반영, 결과에도 섞임. 넣기·옮기기·자르기·점 수정·`음원 자동 조절`·제거는 실행 취소 대상.

## 4. 동작 상세

### 4.1 데이터 (Job.bgms)

`Job.bgms = [{id, file, name, at, in, out, gain, points, touched}]` (`gain` 은 4.2 곡 크기 맞춤 보정 dB) — 제안 형태 (구현자가 다듬어도 됨):

| 키 | 뜻 |
|---|---|
| `file` | 작업 폴더 `bgm/<sha16><ext>` 의 파일 이름 (이미지 `overlays/` 와 같은 방식으로 복사) |
| `name` | 화면 이름 (처음엔 파일 이름) |
| `at` | 결과 영상에서 BGM 이 시작하는 초 |
| `in`/`out` | 곡 안에서 쓰는 구간(곡 초). 처음엔 `0`/곡 길이. `0 ≤ in < out ≤ 곡 길이` |
| `points` | `[[곡 초, dB], …]` 곡 초 순. 사이는 dB 직선 보간, 첫 점 앞·끝 점 뒤는 그 값 유지 |
| `touched` | 점을 손댔는지. `음원 자동 조절` 이 false 로 되돌림 |

- 점을 **곡 초** 로 두는 이유(내 판단): 양끝을 잘라도 곡선이 곡에 붙어 있고, 옮겨도 곡선이 통째로 따라온다.
- 결과 시간 t 에서 곡 위치 = `in + (t - at)`, 들리는 구간은 결과 `[at, at + (out - in)]`.
- 저장: `out/<이름>.bgm.json` → 파이프라인 `--bgm <json>` (`[{path, at, in, out, gain, points}]`). 비면 낡은 파일을 지운다
  (`save_overlays` 와 같은 방식). 실행 취소 스냅숏(`api.py` 의 snap 튜플)에 `bgms` 를 넣는다.

### 4.2 자동 곡선

- 말소리 구간 = 남긴 단어(전사)를 결과 시간으로 옮긴 것. 0.5초 미만 틈은 이어 붙인다 (내 판단, 값은 구현자 재량).
  필요하면 컷 적용 소리 에너지로 보완해도 됨.
- **곡 크기 맞춤 (내 판단):** 불러올 때 곡의 라우드니스(LUFS)를 한 번 재서 기준(제안 -24 LUFS, 말소리 -14 LUFS 보다 작게)에
  맞추는 보정 dB 를 `Job.bgms[].gain` 으로 저장. 곡선의 0dB = 이 보정을 건 크기. 렌더와 미리보기가 같은 `gain` 을 쓴다.
- 기본값(내 판단, 들어 보고 조정): 말 없는 곳 0dB(맞춘 곡 크기), 말하는 곳 -15dB, 오르내림 0.3초에 걸쳐
  (말 시작 0.3초 전부터 내려가 말 시작에 바닥, 말 끝에서 0.3초에 걸쳐 올라옴), BGM 맨 앞뒤 0.5초 페이드 인/아웃.
- 값은 한 곳에 상수로 모아 둔다. 0dB 가 말소리(-14 LUFS 정규화)에 비해 너무 크게 들리면 바탕 값을 낮추는 쪽으로 조정.
- **손대지 않은 BGM** (`touched=false`): 결과 시간이 바뀌는 편집(다시 판정·직접 자르기/되살리기·영상 넣기/빼기/옮기기)
  뒤에 자동 곡선을 다시 계산한다 (내 판단). 손댄 BGM 은 그대로.
- BGM 을 옮기거나 양끝을 자르는 것은 "손댐" 이 아니다 — 손대지 않은 BGM 이면 새 자리 기준으로 다시 계산.
  (내 판단: 점을 끌거나 추가·삭제한 것만 손댐.)

### 4.3 화면

- **시간축 (사용자 결정):** 확대 타임라인은 지금처럼 원본 초 축 그대로 두고, BGM 막대를 그 위에 그린다.
  막대는 원본 축에서 `toOrig(at)` ~ `toOrig(at + 길이)` 를 차지하고(`player.js` 의 `timeMap` 같은 원본↔결과 변환),
  잘린 구간(빗금)은 결과에서 0초라 막대가 그 위를 덮어도 곡은 이어진다 — 음량 선은 빗금 구간에서 평평하게(같은 값으로) 지나간다.
  썸네일·소리·이미지 줄과 세로로 맞는 것이 이 선택의 이유. 따라서 막대 화면 길이 ≠ 곡 길이일 수 있고, 앞쪽 컷이 바뀌면
  막대가 원본 축에서 밀려 보인다(결과 시간은 그대로). 끌기·점 끌기·자리 맞춤·겹침 줄 나눔은 모두 결과 시간으로 바꿔 계산하고
  화면 좌표로만 변환한다 (화면 px 임계값은 화면에서 잰다). 결과 끝을 넘는 부분은 원본 축 끝에서 잘라 그리고, 넘는다는 표시를 둔다.
- **음원 줄:** 확대 타임라인의 이미지 줄 근처에 음원 줄. 겹치는 BGM 은 아래 줄로 내린다 (이미지 줄처럼 자리 나눔).
  패널 높이·스크롤은 이미지 줄 규칙(`TL.lanesDrag`)과 같은 방식으로 함께 다룬다 — 영상 화면이 줄어들지 않게.
- **막대:** 이름, (가능하면) 곡 파형, 음량 선. 고른 막대만 점·`음원 자동 조절` 버튼이 보이고 편집된다 (내 판단).
- **세로 축:** 위 +6dB ~ 아래 무음(-∞). 실제로는 -40dB 아래를 무음으로 다룬다 (내 판단).
- **점:** 선 위를 누르면 그 자리에 점 추가. 점 끌기 = 위아래 음량, 좌우 시점 (이웃 점을 넘지 못함, 막대 밖으로 못 나감).
  점 지우기 = 점 두 번 누르기 또는 고른 점에서 Delete/Backspace (내 판단).
  음원 지우기 = 탭의 `제거`, 타임라인 머리 줄 `제거`, 또는 점이 안 골라진 상태에서 Delete/Backspace (사용 중 요청으로 추가).
- **양끝 손잡이:** 안쪽으로 끌어 `in`/`out` 을 줄인다. 원래 곡 범위 밖으로는 안 늘어난다. 왼쪽 끝을 자르면 `at` 도 같이
  움직여 곡의 나머지 소리 위치는 그대로 (편집 프로그램 트림처럼).
- **끌어 옮기기:** 막대 몸통을 4px 넘게 끌면 옮김 (영상 띠 끌기와 같은 기준). 자리 맞춤 대상:
  결과 0초(BGM 시작), 결과 끝(BGM 끝), 끼워 넣은 영상 띠 경계, 다른 BGM 의 시작·끝. 막대의 시작이나 끝이
  대상과 화면상 몇 px 안에 들면 붙인다 (임계값 구현자 재량, 8px 정도). 계산은 순수 함수로 `app/ui/timeline.js` 에 두고
  `tests/test_timeline_js.py` 로 시험.
- **넣기:** 재생 위치(결과 시간, 프레임 격자)에서 시작. 결과 끝을 넘는 부분은 그대로 두되 들리지 않는다(아래 4.5).
  재생 위치가 결과 끝(들릴 곳이 MIN_LEN 미만)이면 곡 끝을 결과 끝에 맞춰 넣는다. 끌어 옮길 때도 결과 끝에서 MIN_LEN 은 남긴다 (사용 중 발견해 추가).
- **`음원` 탭:** 이미지·영상 탭과 같은 구성과 동작. 보관함은 `<데이터>/bgm_presets/`(presets.json, `<id>/<sha16><ext>`).
  보관에는 파일과 이름만 저장 (곡선은 넣을 때 자동으로 새로 깔린다 — 내 판단).
- 받는 파일: ffprobe 로 소리 스트림이 있는 소리 파일(mp3·m4a·aac·wav·flac·ogg 등). 영상 스트림이 있는 파일은 받지 않는다.
- 화면 문구는 이 문서에 적힌 것을 쓴다 (앱 스펙 3장 규칙의 연장).

### 4.4 미리보기

- 재생기 시간은 이미 결과 시간이다 (`app/ui/player.js`). BGM 은 브라우저에서 섞는다 (권장: Web Audio —
  곡을 디코드해 두고 재생 위치에 맞춰 소스를 예약, GainNode 에 곡선을 dB→배율로 걸기). 재생·멈춤·탐색·편집 때 다시 예약.
- 점을 끌면 다시 렌더 없이 바로 들려야 한다. 파이프라인의 `--preview-cut-audio` 는 말소리만 그대로 둔다.
- 미리보기와 결과의 곡선 계산(보간·dB→배율)은 같은 규칙이어야 한다. 순수 계산은 JS/파이썬 양쪽 시험으로 같은 값을 확인.

### 4.5 렌더 (파이프라인)

- `--bgm <json>` 숨은 옵션 추가 (없으면 기존 동작 그대로).
- 컷 적용한 말소리(`cut_audio` 결과, 렌더용 잡음 제거·음량 맞춤을 거친 것) **뒤에** BGM 을 더한다 → 잡음 제거·loudnorm 이
  BGM 을 건드리지 않는다. `--sequence` 가 있어도 결과 시간 기준이므로 같은 자리에서 섞는다.
- 방법은 구현자 재량. 제안: 각 곡을 ffmpeg 로 말소리와 같은 샘플레이트·채널의 wav 로 풀고, numpy 로 곡선 배율을 곱해
  결과 시간 위치에 더한다. 합이 0dBFS 를 넘으면 리미터(예: ffmpeg `alimiter`)로 클리핑을 막는다.
- 결과 길이(영상 길이) 밖의 BGM 부분은 버린다 — 소리가 영상보다 길어지면 안 된다 (CLAUDE.md 렌더 검증: 영상·오디오 길이 차 1프레임 이내).
- 소리만 있는 입력(m4a 출력)에도 똑같이 섞는다. 자막·새기기·이미지에는 영향 없음. report.md 에 넣은 BGM 목록을 한 줄씩 남긴다 (내 판단).

## 5. 제약

- 기존 CLI 기본 동작은 그대로. 앱 전용 숨은 옵션만 추가.
- `input/` 원본은 건드리지 않는다. 사용자 데이터는 앱 데이터 폴더(`YTEDIT_DATA_DIR`)에.
- 실행 중인 앱은 `app/ui` 를 다시 읽지 않는다 — 확인할 땐 앱을 껐다 켠다.
- 고친 뒤 `.venv/bin/python -m pytest` 전체를 돌린다.
- `h()` 로 목록을 통째로 다시 그리는 화면의 dblclick 문제(CLAUDE.md)가 음원 탭 이름 바꾸기에도 해당.

## 6. 구현자에게 맡기는 것

- 자동 곡선 상수의 정확한 값, 말소리 구간 판정의 세부(단어 기준 + 에너지 보완 여부).
- 미리보기 섞기의 구현(Web Audio 권장)과 렌더 섞기의 구현(numpy 또는 ffmpeg 필터).
- 막대 파형 표시 여부와 방식, 자리 맞춤 px 임계값, 점·손잡이의 모양.
- Job·Api 메서드 이름과 나눔 (기존 `add_overlay`/`add_clip`/`move_clip` 패턴을 따를 것).
- CLAUDE.md 에 새 옵션(`--bgm`)과 음원 탭 설명을 짧게 추가.

## 7. 내가 정한 것 (사용자 확인 전)

- 곡 크기 맞춤(-24 LUFS 기준 보정 `gain`), 점을 곡 초로 저장, 옮기기·트림은 "손댐" 아님, 손대지 않은 BGM 은 편집 뒤 자동 재계산.
- 자동 곡선 기본값(0 / -15dB, 0.3초 램프, 0.5초 페이드), 세로 축 +6dB~무음.
- 고른 막대에서만 점·버튼 표시, 점 지우기 방법, 보관함엔 곡선 저장 안 함, report.md 기록.
