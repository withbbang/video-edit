# /youtube-clean [영상 경로] [옵션]

입력 영상을 `scripts/pipeline.py` 로 처리해 `output/` 에 정리된 영상과 SRT 를 만든다.

## 절차

1. **입력 확인**
   - 경로가 주어지지 않았으면 `input/` 에서 가장 최근 영상 파일(mp4/mov/mkv/m4a/wav)을 고르고 어떤 파일을 쓸지 한 줄로 알린다.
   - `input/` 도 비어 있으면 파일을 `input/` 에 넣어 달라고 요청하고 멈춘다.

2. **환경 확인**
   - `.venv/bin/python` 이 없으면 `./setup.sh` 를 실행한다.
   - 기본값은 아/어/음·습관어·무음 컷과 맥 하드웨어 인코딩이 전부 on 이다. 요청에 따라 끈다:
     "아/어/음은 남겨" → `--filler off`. "습관어는 남겨", "아/어/음만" → `--habit off`.
     "그/저/좀까지 전부 잘라", "공격적으로" → `--habit aggressive` (기본 on 도 그니까/약간/이제 등은 전부 자른다).
     "고화질로", "소프트웨어 인코딩" → `--hw off` (libx264, 느림).
   - 말 사이 빈 구간(무음)도 기본으로 잘린다. "무음은 놔둬", "호흡 살려" → `--silence off`.
     "더 타이트하게"/"여유 있게" 같은 요청은 `fillers.json` 의 `silence_pad_sec`(말 앞뒤로 남기는 초, 기본 0.08)·
     `silence_min_sec`(이보다 짧은 멈춤은 그대로, 기본 0.3)를 바꿔 달라는 뜻이니 확인 후 고친다.
   - "먼저 검토", "뭐가 잘리는지 보고" → `--review` 로 돌리고 3단계 대신 검토표를 보여준다.

3. **실행**
   ```
   .venv/bin/python scripts/pipeline.py <영상> [옵션]
   ```
   포그라운드로 실행하고 기다린다. 긴 영상은 수십 분 걸릴 수 있으니 Bash timeout 을 넉넉히(최대치) 준다.
   타임아웃으로 끊겨도 캐시가 남으므로 같은 명령을 다시 실행하면 이어서 진행된다.

4. **결과 보고** — `output/<이름>.report.md` 와 `output/<이름>.review.md` 를 읽고:
   - 원본 길이 → 결과 길이, 컷 수(그중 무음 컷 수), 제거된 초, 많이 잘린 단어 상위 3개를 요약.
   - review.md 의 문맥 컬럼을 훑어 **의미가 있는데 잘렸을 가능성이 있는 항목**을 최대 5개 짚는다
     (예: "그" 다음에 명사가 오는 경우, "이제"가 "지금"의 뜻으로, "약간"이 "조금"의 뜻으로 쓰인 경우 —
     기본 모드에서 habit 목록은 문맥 없이 전부 잘리므로 특히 이런 항목을 잘 본다).
     `(무음)` 항목은 일일이 짚지 말고, 건너뛴 무음(작은 목소리 의심)이 있을 때만 알린다.
   - 결과 파일 경로(영상, SRT)를 알린다. 유튜브엔 SRT 를 따로 올려야 한다(영상 속 자막 트랙은 유튜브가 쓰지 않음).
   - 되돌리고 싶은 컷이 있으면 번호를 알려 달라고 한 줄로 제안한다.

5. **컷 되돌리기 요청이 오면**
   - `output/<이름>.cuts.json` 의 `cuts` 배열에서 해당 항목을 제거한다 (시작 시간·단어로 식별).
   - `.venv/bin/python scripts/pipeline.py <영상> --apply-cuts output/<이름>.cuts.json` 으로 재렌더.
   - 전사는 다시 하지 않으므로 렌더링 시간만 걸린다.

## 주의

- `input/` 원본은 수정하지 않는다.
- `fillers.json` 은 사용자가 단어를 추가/제거해 달라고 할 때만 고친다. 고친 뒤 재실행하면 캐시된 전사를 써서 빠르다.
- 모델 다운로드(첫 실행, ~1.6GB)나 네트워크 오류는 숨기지 말고 그대로 알린다.
